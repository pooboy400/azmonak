چرخهٔ کامل یک جلسه آزمونک

هرچه در این کتاب می‌خوانی، در قلب همین چرخه می‌چرخد. بار اول که وارد می‌شوی، جایابی (گام ۲) اجرا می‌شود؛ از جلسهٔ بعد مستقیم به انتخاب سؤال می‌روی. پایان هر جلسه هم نمرهٔ وزن‌دار، پیش‌بینی و نمودار روند تولید می‌شود.

شکل ۱ — چرخهٔ پاسخ آزمونک؛ رنگ هر گودال نشان می‌دهد کدام فصل آن را باز می‌کند

موتور Elo — امتیاز هوشمند
قلب تپندهٔ آزمونک: بعد از هر پاسخ، چه کسی چند امتیاز بگیرد یا بدهد؟

در یک آزمون کاغذی، نمرهٔ ۱۸ از ۲۰ فقط یک جمله می‌گوید: «این فصل را خوب بلدی». اما همان نمره اگر از سؤال‌های سخت گرفته شده باشد معنای دیگری دارد تا وقتی از سؤال‌های آسان است. آزمونک می‌خواهد همین تفاوت را عددی و لحظه‌به‌لحظه بسازد؛ پس به جیبی نیاز دارد که بعد از هر تک‌پاسخ، هم دانش‌آموز و هم سؤال را دوباره ارزیابی کند. آن جیب Elo است — همان موتوری که رتبهٔ بازیکنان شطرنج جهان را چند دهه است مدیریت می‌کند.

🧒اگر یک بچهٔ ۱۰ ساله بپرسد: «این Elo دیگر چیست؟»

فرض کن در یک بازی آنلاین رتبه داری؛ مثل لیگِ برنز و نقره و طلا. اگر با کسی هم‌سطح خودت بازی کنی و ببری، رتبه‌ات فقط کمی بالا می‌رود — چون کاری که انتظارش می‌رفت را کردی. ولی اگر با بازیکن خیلی قوی‌تری بازی کنی و او را ببری، رتبه‌ات جهش می‌کند؛ چون کاری کردی که هیچ‌کس فکرش را نمی‌کرد! و اگر برعکس از بچه‌ای کوچک‌تر ببازی، بردنِ تو هیچ‌کس را خوشحال نمی‌کند و رتبه‌ات تقریباً ثابت می‌ماند؛ ولی اگر ببازی، خیلی رتبه از دست می‌دهی.

آزمونک هم دقیقاً همین کار را می‌کند: هر سؤال مثل یک حریف است. سؤالی که نمره‌اش ۱۳۵۰ است مثل یک بازیکن قوی است؛ اگر جوابش بدهی، از او امتیاز می‌گیری. جالب‌تر اینکه خودِ سؤال هم رتبه دارد و آن رتبه با پاسخ بچه‌ها بالا و پایین می‌شود: اگر بچه‌های ضعیف‌تر از حد انتظار به یک سؤال جواب درست بدهند، یعنی آن سؤال «بااحیان» آسان‌تر است و رتبه‌اش کمی پایین می‌آید. مثل این است که همهٔ کلاس به حریف امتیاز بدهند یا بگیرند!

💡مفهوم — دو عدد، یک انتظار، یک سورپرایزهر دانش‌آموز یک «توان» و هر سؤال یک «سختی» روی یک خط‌کش مشترک

کل موتور سه جمله است. اول: از اختلاف دو عدد، «انتظار» ساخته می‌شود — شانسی که دانش‌آموز دارد سؤال را درست جواب بدهد:

E = 1 / ( 1 + 10(Rq − Rs) / 400 )فرمول انتظار — منحنی لجستیک؛ ۴۰۰ ثابت مقیاس است
Eانتظار موفقیت؛ عددی بین ۰ و ۱. اگر توان دانش‌آموز با سختی سؤال برابر باشد، E دقیقاً ۰٫۵۰ می‌شود
Rsتوان دانش‌آموز — شروع ۱۲۵۰ از جلسهٔ جایابی
Rqسختی سؤال — نویسنده برآورد اولیه می‌زند و «رأی جامعهٔ پاسخ‌دهندگان» آن را اصلاح می‌کند
Sنتیجهٔ واقعی: پاسخ درست = ۱، غلط = ۰
Kضریب سرعت یادگیری؛ بزرگ‌نبودنش مهم است — جلوتر می‌بینیم چرا

دوم: سورپرایز اندازه می‌شود؛ یعنی فاصلهٔ «انتظار» تا «واقعیت»: S − E. پاسخ درست به سؤالی که ۷۰٪ شانس درست‌زدنش را داشتی تقریباً هیچ خبری نیست؛ همین پاسخ به سؤالی با ۳۰٪ شانس یک خبر بزرگ است. سوم: هر دو طرف بر اساس همان سورپرایز جابه‌جا می‌شوند — آینه‌وار:

Rs′ = Rs + Ks · ( S − E )      Rq′ = Rq + Kq · ( E − S )آپدیت دوطرفه — آن‌که بهتر از انتظار عمل کند می‌گیرد و دیگری همان را می‌دهد

دقت کن امضای دو فرمول برعکس است: اگر دانش‌آموز از انتظارش بهتر عمل کند (S > E) توانش بالا می‌رود و سختی سؤال پایین می‌آید. ضریب‌های K هم برابر نیستند و نباید باشند: هر پاسخ دربارهٔ «این دانش‌آموز» اطلاعات خیلی زیادی دارد، ولی دربارهٔ «این سؤال» فقط یک رأی از دل هزاران رأی است؛ پس Ks = ۳۲ ولی Kq = ۸. و هر دو با تجربه آرام می‌گیرند تا دیرهنگام نلرزند:

Ks۳۲ تا پاسخ پنجاهم ← ۲۴ تا پاسخ صد و پنجاهم ← ۱۶ بعد از آن
Kq۸ تا پاسخ چهلمِ سؤال ← ۴ بعد از آن (سؤال به سختیِ واقعی‌اش می‌رسد)
شکل ۲ — منحنی انتظار: هر ۴۰۰ امتیاز اختلاف، شانس را ده برابر می‌کند؛ نقطهٔ میانی همان ۵۰٪ است
👨‍💻مهندسی — فایل core/elo.py۳۰ خط پایتون خالص؛ بدون هیچ کتابخانه‌ای

کل موتور Elo در یک فایل کوچک جا می‌شود. سه تابع دارد: محاسبهٔ انتظار، ضرایب متغیر K و آپدیت دوطرفه. کامنت‌ها فارسی‌اند تا موقع خواندن گم نشوی؛ اسم توابع و متغیرها انگلیسی است (طبق D5 — کد انگلیسی، مستندات فارسی).

core/elo.pyبخش ۱ — ثابت‌ها و تابع انتظار
"""موتور Elo آزمونک — رتبه‌بندی دوطرفه دانش‌آموز و سؤال."""

K_STUDENT_START = 32    # K دانش‌آموز در شروع
K_QUESTION_START = 8    # K سؤال در شروع
D_SCALE = 400.0         # ثابت مقیاس لجستیک؛ هر ۴۰۰ امتیاز = شانس ۱۰ برابر


def expected_success(r_student: float, r_question: float) -> float:
    """شانس درست‌زدن دانش‌آموز روی سؤال — فرمول لجستیک Elo."""
    return 1.0 / (1.0 + 10.0 ** ((r_question - r_student) / D_SCALE))


def k_student(total_answers: int) -> int:
    """K متغیر دانش‌آموز: ۳۲ تا ۵۰ پاسخ، ۲۴ تا ۱۵۰، بعد ۱۶."""
    if total_answers < 50:
        return 32
    if total_answers < 150:
        return 24
    return 16


def k_question(total_answers: int) -> int:
    """K متغیر سؤال: هر پاسخ دربارهٔ سؤال اطلاعات کمتری دارد."""
    return K_QUESTION_START if total_answers < 40 else 4
core/elo.pyبخش ۲ — آپدیت دوطرفه پس از هر پاسخ
def apply_result(
    r_student: float,
    r_question: float,
    correct: bool,
    k_s: int = K_STUDENT_START,
    k_q: int = K_QUESTION_START,
) -> tuple[float, float, float]:
    """دانش‌آموز: R' = R + K_s*(S−E) | سؤال: R' = R + K_q*(E−S)

    Returns:
        (توان جدید دانش‌آموز، سختی جدید سؤال، انتظار E قبل از پاسخ)
    """
    e = expected_success(r_student, r_question)
    s = 1.0 if correct else 0.0
    new_student = r_student + k_s * (s - e)
    new_question = r_question + k_q * (e - s)
    return new_student, new_question, e

مثال عددی گام‌به‌گام — همان «تست طلایی» سند اصلی
۱دانش‌آموزی با توان 1200 به سؤالی با سختی 1350 می‌رسد. انتظار: E = 1/(1+10^(150/400)) = 1/(1+2.371) ≈ 0.296 — فقط ۲۹٫۶٪ شانس درست‌زدن.
۲او درست جواب می‌دهد! سورپرایز: S − E = 1 − 0.296 = 0.704 — خبر بزرگ، چون کاری بهتر از انتظار انجام شد.
۳دانش‌آموز: 1200 + 32 × 0.704 = ۱۲۲۲٫۵ — جهشی حدود ۲۲ امتیازی؛ با K متغیر، دفعات بعد این جهش کوچک‌تر می‌شود.
۴سؤال: 1350 + 8 × (0.296 − 1) = 1350 − 5.6 = ۱۳۴۴٫۴ — سؤال کمی آسان‌تر شد؛ این همان «رأی جامعه» بر سختی است. (هر دو عدد با تست خودکار بازتولید می‌شوند: python scripts/test_core_modules.py)

چرا Elo و نه IRT / Glicko-2 / TrueSkill؟ IRT (نظریهٔ پاسخ به سؤال) جامع‌تر است و در توفل و PISA کار می‌کند، ولی برای کالیبره‌شدن به صدها پاسخ در هر سؤال نیاز دارد — بانک سؤال MVP ما ۵۰ تا ۱۵۰ سؤال است و این سرمایه وجود ندارد. """جایابی ۴ سؤالی (D1) — پیدا کردن سطح واقعی دانش‌آموز تازه‌وارد."""

from elo import apply_result

START_RATING = 1250.0    # برآورد خنثی قبل از اولین پاسخ
PLACEMENT_K = 32         # K ثابت در طول جایابی (تصمیم D1)
QUESTION_K = 8           # K سؤال در جایابی
# سه رده سختی با «ترتیب پراکنده» — دنبالهٔ صعودی الگو می‌سازد و حدس می‌آورد
SPREAD = (1250.0, 1150.0, 1350.0)
BASE_UNCERTAINTY = 100.0  # شاخص عدم‌قطعیت پایه = نصف پراکندگی
UNCERTAINTY_DECAY = 15.0  # کاهش عدم‌قطعیت با هر پاسخ
MIN_UNCERTAINTY = 40.0


def next_question_rating(index: int, r_student: float) -> float:
    """سختی سؤال iاُم: سه سؤال اول پخش روی رده‌ها، چهارمی نزدیک برآورد."""
    if index < len(SPREAD):
        return SPREAD[index]
    return min(1350.0, max(1150.0, r_student))


def run_placement(answers: list[bool]) -> dict:
    """کل جلسهٔ جایابی؛ خروجی: R_s اولیه + شاخص عدم‌قطعیت + ردپا."""
    r_student = START_RATING
    trace = []
    for i, correct in enumerate(answers):
        r_question = next_question_rating(i, r_student)
        new_student, new_question, e = apply_result(
            r_student, r_question, correct, PLACEMENT_K, QUESTION_K
        )
        trace.append({
            "step": i + 1, "r_question": r_question,
            "expected": round(e, 3), "correct": correct,
            "r_student": round(r_student, 1),
            "r_student_new": round(new_student, 1),
        })
        r_student = new_student
    uncertainty = max(
        MIN_UNCERTAINTY,
        BASE_UNCERTAINTY - UNCERTAINTY_DECAY * len(answers),
    )
    return {"r_student": round(r_student, 1),
            "uncertainty": uncertainty, "trace": trace}

لایهٔ اول — ناحیهٔ هدف ۶۵٪ تا ۷۵٪. فرمول انتظار فصل ۱ برای هر سؤالِ کاندید یک عدد می‌دهد؛ سیاست، سؤالی است که این شانس داخل بازه باشد و عملیاتی‌کردنش یعنی انتخاب کمینهٔ فاصله از میانه:

q* = argminq ∈ Candidates | E(Rs, Rq) − 0.70 |معیار کمینهٔ فاصله از نقطهٔ هدف ۰٫۷۰ — از اسلایدهای سند

چرا ۷۰٪ و نه ۵۰٪؟ در ۵۰٪ عملاً با شانس سکه جلو می‌روی؛ اضطراب بالا می‌رود و بازخورد کم‌اطلاع می‌شود. چرا نه ۹۰٪؟ چون آن‌جا دیگر «چالش» نیست؛ نمرهٔ بالا فقط خودفریبیِ آسان‌گرایی می‌سازد. ۷۰٪ نقطهٔ تعادل حسِ پیشرفت و چالش واقعی است و بازهٔ ۶۵–۷۵٪ هم اجازهٔ تنفس می‌دهد. نکتهٔ جالب ریاضی: چون ۷۰٪ یعنی سؤال باید «کمی آسان‌تر از توان تو» باشد، این ناحیه معمولاً کمی پایین‌تر از Rs تو قرار می‌گیرد — این باگ نیست، جنسِ تعریف E است.

لایهٔ دوم — امتیاز ارزش آموزشی. معمولاً چند سؤال هم‌زمان داخل ناحیه‌اند؛ این‌جا سیاست از «سخت کدام» به «مفید کدام» سوییچ می‌کند. هر کاندید جمع وزنی سه مؤلفه می‌گیرد:

V(q) = w1 · Weakness(cat) + w2 · Importance(topic) + w3 · Recency(q)وزن‌ها ۰٫۵ / ۰٫۳ / ۰٫۲ — پیش‌فرض مهندسی و قابل وتو

Weakness از نردبان سطح (فصل بعد) می‌آید: دسته‌ای که سطحش افتاده امتیاز بیشتری می‌گیرد. Importance ارزش مبحث در سرفصل است که نویسندهٔ محتوا ست می‌کند. Recency هم فاصلهٔ زمانی از آخرین برخورد با آن مبحث است تا مباحث رهاشده کم‌کم بالا بیایند و «فراموشی محض» رخ ندهد.

لایهٔ سوم — محدودیت مواجهه. آخرین فیلتر حفاظتی: سؤالی که در ۲۰ پاسخ اخیر دیده شده، از کاندیدها حذف می‌شود (exposure_window = 20). بدون این فیلتر، سیاست ارزش آموزشی ممکن است «عاشق» یک سؤال شود و هر جلسه تکرارش کند؛ نتیجه، حفظِ صورتِ سؤال و تورم مصنوعی نمره است. و یادت باشد: نوار سختیِ کل این انتخابات، از سطحِ جاری نردبانِ آن دسته (فصل بعد) می‌آید — دو موتور دست در دست هم کار می‌کنند.

👨‍💻مهندسی — فایل core/selector.pyسه فیلتر در یک تابع انتخاب؛ فال‌بک هوشمند برای بانک‌های کم
"""انتخاب سؤال سه‌لایه — ناحیهٔ هدف، ارزش آموزشی، محدودیت مواجهه."""

from elo import expected_success

TARGET = 0.70                    # میانهٔ ناحیهٔ هدف
ZONE_LOW, ZONE_HIGH = 0.65, 0.75 # ناحیهٔ هدف (پیوست الف)
EXPOSURE_WINDOW = 20             # پنجرهٔ مواجهه (گپ G8)
W_WEAKNESS = 0.5                 # وزن ضعف دسته
W_IMPORTANCE = 0.3               # وزن اهمیت مبحث
W_RECENCY = 0.2                  # وزن تازگی


def educational_value(weakness: float, importance: float,
                      recency: float) -> float:
    """V(q) = ۰٫۵·ضعف + ۰٫۳·اهمیت + ۰٫۲·تازگی (ورودی‌ها بین ۰ و ۱)."""
    return W_WEAKNESS * weakness + W_IMPORTANCE * importance \
        + W_RECENCY * recency
core/selector.pyبخش ۲ — تابع اصلی انتخاب
def select_question(r_student: float, candidates: list[dict],
                    recent_question_ids: list[int]) -> dict | None:
    """بهترین سؤال بعدی؛ هر آیتم کاندید شامل id، r_question،
    weakness، importance، recency است."""
    # لایهٔ ۳ — محدودیت مواجهه: دیده‌شده‌های ۲۰ پاسخ اخیر حذف
    seen = set(recent_question_ids[-EXPOSURE_WINDOW:])
    pool = [c for c in candidates if c["id"] not in seen]
    if not pool:
        return None

    # لایهٔ ۱ — ناحیهٔ هدف (فال‌بک: نزدیک‌ترین به ۰٫۷۰)
    for c in pool:
        c["e"] = expected_success(r_student, c["r_question"])
    zone = [c for c in pool if ZONE_LOW <= c["e"] <= ZONE_HIGH]
    if not zone:
        return min(pool, key=lambda c: abs(c["e"] - TARGET))

    # لایهٔ ۲ — بیشترین ارزش آموزشی
    for c in zone:
        c["value"] = educational_value(
            c["weakness"], c["importance"], c["recency"])
    return max(zone, key=lambda c: c["value"])

💡مفهوم — کیفیت سه‌سیگنالی و فرمول درجه‌دو

کیفیت هر پاسخ، q نام دارد و بین ۰ تا ۵ است؛ در آزمونک از سه سیگنال ساخته می‌شود، نه فقط درست/غلط: ① درستی — پایه: درست ← ۴، غلط ← ۲. ② اعتماد (D14) — «مطمئن بودم» یک امتیاز اضافه می‌کند (سقف ۵)؛ «حدس می‌زدم» ولی درست، سقف q را در ۴ می‌بندد — چون حدسِ درست نباید حافظهٔ واقعی قوی‌تری نشان بدهد. ③ تأخیر (D10) — پاسخِ زیر ۱۵ ثانیه مشکوک به حدس رفلکسی است (سقف q = ۴) و بالای ۷۰ ثانیه یعنی سخت به جواب رسیده‌ای (−۰٫۵). سیگنال اعتماد فقط همین‌جا و در قرینهٔ بدفهمی مصرف می‌شود و وارد نمرهٔ جلسه نمی‌شود — قاعدهٔ ثابت سند.

دو عدد هر آیتم با q به‌روز می‌شوند. اول آسانی نسبی؛ اگر d = 5 − q را باز کنی، فرمول SM-2 شکل حساب‌شده‌اش را نشان می‌دهد:

EF′ = EF + ( 0.1 − d · 0.08 − d2 · 0.02 )     d = 5 − q   ,   EF ≥ 1.3قانون آپدیت آسانی نسبی — جریمه درجه‌دو برای کیفیت بد؛ کف ۱٫۳

سه خاصیت از همین بازکردن بیرون می‌آید: در q = ۴، د = ۱ است پس 0.1 − 0.08 − 0.02 = 0 و EF دست‌نخورده می‌ماند؛ در q = ۵ فقط ۰٫۱ اضافه می‌شود (رشد آهسته و صبور)؛ و هرچه q بدتر شود، جملهٔ d² سنگین‌تر از جریمهٔ خطی رشد می‌کند — کیفیتِ خیلی بد، سقوط EF را تندتر می‌کند. سپس فواصل:

q < 3 ⇒ reset  |   I(1) = 1  ,   I(2) = 6  ,   I(n) = I(n−1) × EFزنجیرهٔ مرور — یک غلطِ واقعی (q زیر ۳) زنجیره را به روز اول برمی‌گرداند
شکل ۴ — زنجیرهٔ مرور یک آیتم سالم؛ هر پرش = ضرب در EF همان آیتم

یک ظرافت اجرایی: آستانه‌های تأخیر (۱۵ و ۷۰ ثانیه) پیش‌فرض سراسری‌اند و هر سؤال می‌تواند با فیلد est_time_sec خودش آن‌ها را override کند — سؤال محاسباتی سنگین حق دارد زمان بیشتری بخواهد. و «مطمئن اما غلط» (q پایینِ با اعتماد بالا) مهم‌ترین سیگنال انفرادی کل محصول است: همان قرینهٔ بدفهمی که در گزارش جلسه ثبت می‌شود.

"""SM-2 آزمونک — مرور فاصله‌دار با کیفیت سه‌سیگنالی."""

EF_START = 2.5      # آسانی نسبی اولیه
EF_FLOOR = 1.3      # کف EF — هرگز زیر آن نمی‌رود
T_FAST = 15         # ثانیه؛ زیر آن: حدس رفلکسی (سقف q=۴)
T_SLOW = 70         # ثانیه؛ بالای آن: سخت به جواب رسیده (−۰٫۵)
BASE_CORRECT = 4.0  # q پایه برای پاسخ درست
BASE_WRONG = 2.0    # q پایه برای غلط (زیر ۳ ← ریست فاصله)
CONFIDENT_BONUS = 1.0  # «مطمئن بودم» +۱
GUESS_CAP = 4.0     # سقف q برای «حدس می‌زدم ولی درست»


def quality(correct: bool, confident: bool | None,
            elapsed_sec: float) -> float:
    """کیفیت q بین ۰ تا ۵ از سه سیگنال پاسخ."""
    q = BASE_CORRECT if correct else BASE_WRONG
    if confident is True:
        q = min(5.0, q + CONFIDENT_BONUS)
    elif confident is False and correct:
        q = min(q, GUESS_CAP)  # حدسِ درست، حافظه واقعی قوی‌تر نیست
    if elapsed_sec < T_FAST:
        q = min(q, 4.0)        # پاسخ آنی مشکوک به حدس رفلکسی
    elif elapsed_sec > T_SLOW:
        q -= 0.5               # تلاش طولانی = یادگیری متزلزل‌تر
    return max(0.0, min(5.0, q))

def update_ef(ease_factor: float, q: float) -> float:
    """EF' = EF + 0.1 − d·0.08 − d²·0.02 که d = 5 − q؛ کف ۱٫۳."""
    d = 5.0 - q
    new_ef = ease_factor + 0.1 - d * 0.08 - d * d * 0.02
    return max(EF_FLOOR, new_ef)


def next_interval(repetition: int, ease_factor: float, q: float,
                  previous_interval: int = 0) -> int:
    """فاصلهٔ مرور بعدی برحسب روز؛ q<3 یعنی ریست به ۱ روز."""
    if q < 3.0:
        return 1
    if repetition <= 1:
        return 1
    if repetition == 2:
        return 6
    return max(1, round(previous_interval * ease_factor))

آخرین پازل داشبورد: عددی که به دانش‌آموز می‌گوید «اگر همین‌طور ادامه بدهی، جلسهٔ بعد حدوداً این‌قدر می‌گیری». این عدد دو وظیفه دارد: انگیزه‌سازی صادقانه و روایت‌سازی برای داوری («سیستم ما روند یادگیری را پیش‌بینی می‌کند»). ولی پیش‌بینیِ روی نمرهٔ خام، فریب است — ۷۰٪ از سؤال‌های آسان با ۷۰٪ از سؤال‌های سخت یکی نیستند. پس اول نمرهٔ جلسه باید «سخت‌گیرانه» تعریف شود (D13) و بعد روندش مدل شود.

🧒اگر یک بچهٔ ۱۰ ساله بپرسد: «چطور نمرهٔ جلسهٔ بعدی من را حدس می‌زند؟»

معلم‌تان را تصور کن که برگه‌های ده‌تایی‌ات را نگه داشته و می‌گوید: «این هفته‌ها همیشه بهتر شدی؛ آخرین برگه‌ها هم خوب بودند — به نظرم جلسهٔ بعد حدود ۷۵ می‌گیری». آزمونک هم همین کار را می‌کند ولی منصفانه‌تر: برگه‌های آخر را بیشتر جدی می‌گیرد (شاید هفتهٔ اولت بد بود چون تازه بودی!) و برگه‌های خیلی قدیمی را کم‌کم فراموش می‌کند.

و نکتهٔ مهمِ انصاف: سؤال سختِ درست‌زده بیشتر نمره دارد! اگر کسی فقط سؤال‌های آسان را بزند، نمره‌اش همان‌قدر بالا نمی‌رود — مثل این است که معلم بگوید «ده تا درست زدی ولی همه‌شان از بخش‌های آسان بود، پس نمرهٔ کامل نمی‌گیرم». همان هفت‌تای درست، اگر از سؤال‌های سخت باشد، نمرهٔ خیلی بهتری می‌آورد!

💡مفهوم — اول نمرهٔ منصفانه، بعد روندِ وزن‌دار

گام اول — نمرهٔ جلسه (D13). هر سؤال، وزنی برابر با ردهٔ سختی‌اش می‌گیرد: آسان (۱۱۵۰) ×۱، متوسط (۱۲۵۰) ×۱٫۵، سخت (۱۳۵۰) ×۲. نمرهٔ جلسه یعنی سهمِ وزنیِ درست‌ها از کل وزن:

Score = Σ ( wi × si ) ÷ Σ wi × 100نمرهٔ وزن‌دار جلسه — وزن تابع سختی Elo سؤال؛ سیگنال اعتماد عمداً این‌جا نیست

گام دوم — رگرسیون روند. پیش‌بینی، میانگینِ وزن‌دارِ نماییِ نمره‌های جلسات است: جلسهٔ آخر وزن λ⁰ = 1، یکی مانده‌به‌آخر λ = 0.85، دوتا مانده λ² ≈ 0.72 و به همین ترتیب. λ = ۰٫۸۵ یعنی «حافظهٔ بلندمدت با احتیاط»: جلسات اخیر حاکم‌اند ولی گذشته هنوز صدا دارد. پیش از ۸ جلسه، پیش‌بینی اصلاً نمایش داده نمی‌شود — عددِ کم‌پایه اعتماد می‌سوزاند. توان R_s هم جداگانه در نمودار روند رسم می‌شود (D15): نمره برای دانش‌آموز، Rs برای روایت دفاع.

👨‍💻مهندسی — فایل core/predict.pyسه تابع: وزن سختی، نمرهٔ جلسه، پیش‌بینی روند
"""پیش‌بینی نمره — نمرهٔ وزن‌دار D13 + رگرسیون نمایی λ."""

LAMBDA = 0.85            # وزن نمایی جلسات اخیر
MIN_SESSIONS = 8         # حداقل جلسه برای نمایش پیش‌بینی
TIER_WEIGHTS = {1150: 1.0, 1250: 1.5, 1350: 2.0}


def question_weight(r_question: float) -> float:
    """وزن سؤال از سختی Elo — نزدیک‌ترین ردهٔ ۱۱۵۰/۱۲۵۰/۱۳۵۰."""
    nearest_tier = min(TIER_WEIGHTS, key=lambda t: abs(t - r_question))
    return TIER_WEIGHTS[nearest_tier]


def session_score(answers: list[tuple[bool, float]]) -> float:
    """نمرهٔ وزن‌دار: Σ(وزن×درستی) ÷ Σ(وزن) × ۱۰۰."""
    total_weight = 0.0
    earned_weight = 0.0
    for correct, r_question in answers:
        w = question_weight(r_question)
        total_weight += w
        if correct:
            earned_weight += w
    if total_weight == 0:
        return 0.0
    return earned_weight / total_weight * 100.0


def predict_next_score(session_scores: list[float],
                       lam: float = LAMBDA) -> dict:
    """میانگین نمایی وزن‌دار؛ i=۰ یعنی آخرین جلسه."""
    if len(session_scores) < MIN_SESSIONS:
        return {"available": False,
                "reason": f"حداقل {MIN_SESSIONS} جلسه لازم است"}
    weights = [lam ** i for i in range(len(session_scores))]
    forecast = (sum(w * s for w, s in zip(weights, session_scores))
                / sum(weights))
    naive_mean = sum(session_scores) / len(session_scores)
    return {"available": True, "forecast": round(forecast, 1),
            "naive_mean": round(naive_mean, 1),
            "direction": "up" if forecast >= naive_mean else "down"}
